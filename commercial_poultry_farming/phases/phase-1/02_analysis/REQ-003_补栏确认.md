# REQ-003 补栏确认 — 需求分析摘要

> 本文档为 `REQ-003.yaml` 的可读摘要，字段以 YAML 为准。

## 概要

对孵化场送达养殖栋舍雏苗进行签收确认（附录仍残留「雏苗签收」命名，页面URL仍含 chick-sign，以本模块「补栏确认」状态口径为准）。补栏确认主数据按补栏计划日期提前生成（计划编号/上苗日期/栋舍/品种，确认状态默认「待发货」），生成时即分配「栋舍养殖批次」编号（PC-yyyy-栋舍编号-xx），无需等首次确认上孵明细。孵化端发货确认后回填上苗数量/平均苗重并更新确认状态。孵化发货单分三层；支持按发货明细单个确认、批量确认。批次供死淘巡检、饲养日志等下游模块引用。

## 业务规则

- 补栏确认根据补栏计划日期提前生成；与是否已确认上孵明细无关
- 生成补栏确认时即分配栋舍养殖批次（PC-yyyy-栋舍编号-xx）；待发货阶段列表批次列已有值
- 数据生成方式：排程计划下推后生成补栏计划及补栏确认部分主数据：补栏计划编号、上苗日期、栋舍、品种、确认状态(待发货)
- 孵化端发货确认后生成/更新：上苗数量（实际发货量）、平均苗重（实际苗均重）、确认状态
- 孵化发货单分3层：第一层发货单主信息（订单号=补栏计划号、发苗数量、苗重等）；第二层发货明细（对应孵化端上孵明细计划）；第三层每个发货明细数据对应的苗放置具体位置记录
- 孵化发货单状态：待发货/发货中/已发货/已签收
- 确认状态推导：发货单=待发货 → 确认状态=待发货；发货单=发货中 且不存在已确认明细 → 待确认；发货单=发货中 且存在已确认明细且未全部确认 → 部分确认；发货单=已发货 且不存在已确认明细 → 待确认；发货单=已发货 且存在已确认明细且未全部确认 → 部分确认；发货单=已发货 且发货明细全部确认 → 已完成；发货单=已签收 → 已完成
- 点击「确认」：只要存在任意一个发货明细被确认，即更新主表状态为部分确认（批次已在生成补栏确认时分配，确认不再新建批次）
- 若发货单状态为已发货 且发货明细数据全部确认后，更新主表状态为已完成，并推送消息到孵化端，孵化端据此更新发货状态为已签收

## 原型要点

- 查询条件：上苗日期、状态
- 列表列（按序）：序号 → 栋舍养殖批次 → 计划编号 → 上苗日期 → 栋舍 → 确认状态 → 蛋源 → 品种 → 雏苗数量 → 苗重(g) → 免疫信息 → 孵化批次 → 发货单号 → 操作
- 关键按钮语义：
  - **确认**：打开确认弹窗，展示左侧上孵计划明细列表与右侧笼位明细列表，支持单个/批量确认发货明细
  - **导出**：按当前查询条件导出列表（原型工具栏可见，需求文字未详述导出列范围）
  - **明细**：查看发货明细/苗放位置只读明细，具体触发范围与「确认」弹窗关系需与开发确认（见open_questions）
- 嵌套弹窗：
  - 补栏确认（input）：触发于 列表行「确认」按钮 / 工具栏「确认」按钮（批量）
- 子表：
  - 左侧-上孵计划明细列表（所属：补栏确认弹窗）
  - 右侧-笼位明细列表（所属：补栏确认弹窗）
- 保存/提交拦截规则：
  - 存在任意一个发货明细确认后，主表状态更新为部分确认（批次已存在）
  - 发货单状态为已发货且发货明细全部确认后，主表状态更新为已完成并推送签收消息到孵化端
- UI组件：pagination、cell_ellipsis_tooltip、export

## 总体关联（跨模块/外部系统）

- 补栏计划（REQ-002）：主数据来源（计划编号/上苗日期/栋舍/品种，确认状态默认待发货）
- 孵化发货系统（外部）：发货单主信息/发货明细/苗放位置明细提供；确认完成后回推「已签收」状态
- 死淘巡检（REQ-004）/饲养日志（REQ-005）：消费本模块生成的「栋舍养殖批次」编号作为下游记录主键

- 跨模块引用明细：
  - 主数据（计划编号/上苗日期/栋舍/品种/确认状态默认待发货） ← REQ-002（系统自动生成（排程下推，非用户选择弹窗））
