## 测试范围

### 范围内
- 从“计划管理 / 雏苗发货”上下文进入发货执行页，并验证正式路由 `/biopark-breeding/breeding/delivery/execute/{id}` 的页面承接；原型路由仅作为 page.json 已采集证据引用。
- 发货单主表、实际可发数、发货进度、发货状态、关联上孵计划、栋舍工作区和发货记录的可见展示。
- 上孵计划进度、发货状态、计划号关键字筛选、查询和重置，以及无数据/加载失败可见态。
- 已出雏且待发货数大于零的计划进入发货模式；终止计划不在发货执行列表展示，未出雏或待发货数为零的计划入口不可用。
- 发货模式下当前计划进入编辑状态、其他计划入口不可用，以及退出发货和完成发货确认状态。
- 位置录入弹窗中的栋舍/列/层位置、发货数量和备注可见交互；0/负数、小数、超剩余数失焦自动校正，汉字/字母等非数字字符不可输入。
- 同一位置再次打开时数量和备注回显，修改后按最新值保存；覆盖多位置暂存及剩余待发货数重算。
- 无草稿退出、有草稿退出确认、完成确认在未发货数为零或大于零时的可见行为，以及取消不提交、确定提交并退出。
- 确认结束后的提交成功可见结果：位置、计划、发货单进度/状态和发货记录联动；刷新后 mock 初始态恢复仅作为既有页面证据，不等同正式持久化结论。
- 待发货、发货中、已发货、已签收发货单状态下的编辑入口可用性；权限不足、重复提交和并发最新数量校验的页面可观察结果。

- REQ-PC-043 发货单明细、来源明细和只读追溯。
- REQ-PC-044 实际导出文件生成、下载和文件内容校验。
- APP 发货执行、移动端刷新/返回/签收展示规则。
- 发货草稿持久化保存规则、商品禽养殖端签收回写、操作人/操作时间审计要求。
- 库存查询、出入库记录页面字段展示；页面字段由 REQ-PC-045/046 只读验证。
- 发货执行主责验证部分发货不生成出库记录且不扣库存、全部发货后生成出库记录并按累计发货数扣减库存。
- 具体接口路径、HTTP 方法、请求/响应字段、错误码、权限编码和接口独立测试。
- 未由需求或 page.json 已采集状态确认的按钮、字段、菜单、定位器和视觉实现结论。

## 测试策略
- 以需求说明书和 REQ-PC-042 分析 YAML 为业务规则依据，以 page.json 的 capture_id、页面路由、page_id、state_id、元素和 evidence 为页面事实边界。page.json 的 capture.status 为 partial，正式页面结构不得视为完整确认。
- 使用等价类划分覆盖计划进度、发货单状态、日期可执行性、实际可发/待发货数、草稿、位置和提交状态；使用边界值覆盖实际可发为 0、待发货为 0/1/最大值、数量 0/负数/小数/1/等于剩余/超过剩余。
- 使用判定表评估已出雏、计划日期、待发货数、发货单状态、是否处于发货模式、是否有草稿、数量有效性、自动校正、重复提交和并发最新剩余数量的组合。
- 使用状态转换覆盖 page.json 已采集的 `st-default`、`st-filter-progress`/`st-status-filter`、`st-ship-mode`、`st-location-dialog`、`st-location-overlimit`、`st-draft`、`st-exit-draft-confirm`、`st-complete-confirm`、`st-submitted`、`st-reset`。页面状态缺失或正式环境不一致时记录阻塞，不补造状态。
- 使用 Pairwise/2-way 评估计划进度、发货状态、日期资格、实际可发、累计量、待发货、草稿、位置、数量类别、提交状态、当前计划和操作状态的组合；约束包括终止计划不展示、编辑中其他计划不可操作、数量先按失焦规则校正后保存、非数字不可输入、重复提交后一次失败、并发超最新剩余不得提交。
- 自动化仅规划 Playwright Python 可视 Chromium（`headless=False`）。优先使用 page.json 已记录的 role、label、placeholder 和区域语义定位。重复的计划发货入口和栋舍位置格需在正式执行前确认计划号/栋舍/列/层唯一作用域或正式 `data-testid`，不得编造定位器。
- Web 执行采用先导航并等待可观察状态，再操作并保存前后状态证据的方式；不使用固定 sleep，不写入账号、密码、Token、Cookie 或真实业务值。正式提交仅在授权测试数据和清理责任明确后执行。
