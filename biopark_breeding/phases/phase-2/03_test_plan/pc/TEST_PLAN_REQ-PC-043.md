## 测试策略
- 以 REQ-PC-043 分析和需求说明书为业务契约，以 page.json capture_id、page_id、已采集 route、state_id、element_id、DOM/截图路径为页面事实边界；page.json capture.status=partial，正式页面结构、接口、权限和数据不视为已完整确认。
- 使用等价类划分覆盖发货单状态、计划进度、筛选结果、关键字匹配、权限、栋舍范围、视图模式、位置来源和记录数量；使用边界值覆盖有效计划为 0/1/多条、来源计划为 0/1/多条、记录为 0/1/多条、筛选有结果/无结果和终止计划排除。
- 使用判定表评估查看权限、有效计划存在性、筛选结果、是否终止、栋舍范围、视图模式、位置来源、发货记录和重置/清空动作的组合，重点确认只读和空态规则。
- 使用状态转换覆盖 page.json 已采集的 `st-default`、`st-house-overview`、`st-house-current`、`st-house-list`、`st-source-detail`、`st-filter-dropdown`、`st-filter-shipped`、`st-filter-empty`、`st-filter-reset`、`st-doc-01/st-doc-03/st-doc-04/st-doc-05/st-doc-06/st-doc-07/st-doc-08`；未采集或正式环境不一致的状态记录为待确认，不补造结构。
- 使用 Pairwise/2-way 评估 OrderStatus、PlanProgress、FilterResult、HouseScope、ViewMode、PositionSource、RecordState、FilterAction、PermissionState 的组合；约束包括终止计划排除、无结果时三块均暂无数据、筛选/重置默认第一条、总览/当前计划范围不同和所有允许操作只读。

- 自动化规划采用 Playwright Python 可视 Chromium（`headless=False`）；优先使用 page.json 已记录的 role、label、placeholder 和页面区域语义定位。位置明细、记录展开和来源明细弹窗存在重复/未采集定位器风险，正式执行前必须确认行级唯一作用域或 data-testid，不得编造定位器。
- Web 执行按导航、可观察状态等待、操作前后状态比对和证据采集执行；不使用固定 sleep，不执行任何业务写入，不保存账号、密码、Token、Cookie 或真实敏感数据。
