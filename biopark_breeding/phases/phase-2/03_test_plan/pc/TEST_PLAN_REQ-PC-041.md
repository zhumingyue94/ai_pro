## 测试策略

- 以当前需求说明书及用户补充答案为最高优先级，以分析 YAML 为追溯和阻塞基线；页面 DOM/截图仅证明已采集的页面事实，不将历史状态下拉或 mock 数据当作当前实现结论。
- 采用等价类、边界值、判定表、状态转换和 Pairwise/2-way：覆盖日期、栋舍、品种、关键字、五类状态、结果集、权限和浏览器组合，并应用业务约束。
- 按 L1 页面/板块、L2 字段/列/状态展示、L3 来源/格式/值/计算/跨系统一致性分别规划。
- 发货入口按待发货、发货中、已发货、已签收、未来日期独立判定，不合并复合预期。
- 按 Playwright Python + 可视 Chromium 规划自动化范围；优先语义定位，日期分段控件、通用下拉及重复行入口需先确认稳定定位器。
- 证据包含页面状态、截图、DOM、浏览器日志和 trace，并区分已有原型证据与正式环境待采集证据。
