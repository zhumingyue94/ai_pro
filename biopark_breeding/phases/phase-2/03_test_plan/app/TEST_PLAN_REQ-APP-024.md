# 测试计划

## 执行摘要
- **计划编号**：TEST_PLAN-REQ-APP-024
- **模块**：APP 上孵计划发货记录
- **需求**：REQ-APP-024
- **状态**：draft；本阶段仅输出测试计划。
- **输入**：需求说明书、需求变动、REQ-APP-024 分析文件、page.json、页面映射、.env、Schema 和原型入口。

基于 `app-plan-shipment-records` 的已采集状态，规划上孵计划记录的状态、数量、历史、多位置、未找到、签收和折叠边界。page.json Schema 状态为 `input_missing`，采集状态为 `partial_corrected`，原型默认全展开且无折叠按钮的偏差保留为风险。

## 测试范围
### 范围内
- `/m/orders/{发货单号}/plan-shipments/{上孵计划内部ID}` 的待发货、发货中、已发货、已签收、空态和未找到状态。
- 实际可发、累计发货、待分配、进度、提交时间倒序、多列层位置和完成/未完成记录。
- 服务端状态优先、外部签收未确认不得显示已签收、返回执行页和折叠/展开需求。

### 范围外
- 发货确认提交、发货单列表筛选、存发苗间出入库和库存查询。
- page.json 未出现的接口字段、错误码、菜单、按钮或定位器。

## 测试策略
等价类/边界值覆盖未找到、空态、1-3 条、超过 3 条、多位置和完成状态；状态转换覆盖待发货、发货中、已发货、已签收、未找到和返回；判定表组合数量、进度、签收和记录存在性；Pairwise 评估计划状态、记录集、位置、签收结果、来源路由和浏览器。自动化和证据仅使用 page.json 已采集内容，不生成脚本。
