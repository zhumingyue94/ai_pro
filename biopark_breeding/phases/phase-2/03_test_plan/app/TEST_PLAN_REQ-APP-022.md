# 测试计划

## 执行摘要
- **计划编号**：TEST_PLAN-REQ-APP-022
- **模块**：APP 发货执行
- **需求**：REQ-APP-022
- **状态**：updated_for_complete_coverage；已同步新增状态、来源、边界、自动出库和结果恢复用例。
- **输入**：需求说明书、需求变动、REQ-APP-022 分析文件、page.json、.env、Schema 和原型入口。

基于 `app-chick-shipment-execute` 及已采集 `app022-*` 状态，规划执行页统计、发货弹窗、数量/列层/备注、并发、幂等和自动出库边界。`app022-validation-no-position` 保留为原型校验缺陷，不作为通过事实。

## 测试范围
### 范围内
- `/m/orders/{发货单号}/execute` 执行页计划卡、汇总、进度、实际可发、累计和待分配统计。
- 已采集发货弹窗、列层选择、数量、备注、取消/确认及数量校验状态。
- 正整数、待分配上限、服务端最新数量、重复提交、并发、刷新重查、部分/全部发货状态及自动出库和库存扣减联动时机规划。发货执行主责验证：部分发货不联动，全部发货后按累计数量联动。

### 范围外
- 列表筛选和发货记录页面展示。
- page.json 未采集的接口路径、错误码、按钮和稳定定位器。
- 实际业务提交之外的 UI 脚本生成。

## 测试策略
- 等价类/边界值：空、0、负数、小数、1、等于待发、超过待发、备注空值/15字/超过15字。
- 判定表：有效列层、数量、待分配数量、计划状态、权限、库存和签收状态。
- 状态转换：执行默认、弹窗、校验失败、成功刷新、发货中、已发货。
- Pairwise/2-way：计划状态、列、层、数量类别、备注长度、权限和网络结果，约束不超发和不负库存。
- 自动化仅规划 `exec-page`、`plan-list`、`ship-dialog` 等 page.json 元素；不生成脚本。确认发货属于业务变更，必须授权并登记清理。

## 测试环境
- **客户端**：APP 移动端 Web/移动端模拟；**操作系统**：win32
- **浏览器**：Chromium headed；Playwright Python 规划禁止固定等待
- **正式地址**：`${UI_TEST_URL}`
- **页面路径**：`/m/orders/{发货单号}/execute`
- **门户入口**：种禽孵化管理系统 / APP / 发货执行
- **登录**：正式凭据仅从 `.env` 或运行时环境读取，不写入计划、日志或证据。

## 测试数据与角色
准备待分配大于零/为零、有效列层、数量边界、备注边界、服务端数量变化、并发、库存充足/不足和上孵计划批次样本。测试负责只读及经授权变更验证；业务确认数量/位置/状态；研发确认服务端最新数量、幂等和刷新；库存负责人确认分配和不负库存；数据负责人登记清理。

## 依赖与风险
依赖园区列层、发货单、上孵计划、存发苗间库存、自动出库及外部状态服务。风险包括列层空值原型缺陷、mock 成功不等于真实落库、重复/并发可能重复记录或超发，以及未采集接口契约不可编造。

## 准入标准
需求、分析、page.json、.env 和 Schema 可读取；partial/input_missing、列层缺陷和 mock 边界已登记；授权角色、脱敏数据、并发窗口和清理责任已确认。

## 准出标准
数量、位置、备注、状态、并发、库存联动和证据要求完整；三类套件为计划级内容；YAML 已通过 Schema；未生成测试点、用例或脚本。

## 证据要求
引用 `app-chick-shipment-execute`、`app022-exec-default`、`app022-ship-dialog`、数量校验和已发货状态，以及 `exec-page`、`exec-summary-card`、`exec-progress`、`ship-dialog-column`、`ship-dialog-row`、`ship-dialog-quantity`、`ship-dialog-remark`、`ship-dialog-cancel`、`ship-dialog-confirm` 等已采集元素。业务变更证据必须脱敏并包含回读、责任人和清理状态。
