## 3. 已确认业务规则

- 存发苗间库存查询属于 PC 与 APP 共用业务能力。
- 发货执行全部完成后，库存查询可只读回读对应库存字段。
- 出库记录生成时机、库存扣减时机及变动数量由 REQ-PC-042 负责，本模块不重复验证。
- 出入库记录类型、方式、单位等字段由 REQ-PC-046 负责验证。
- 出库批次取上孵计划批次。
- 操作人和操作时间取雏苗发货记录。
- 养殖客户取当前园区。
- 出库存发苗间由上孵计划关联关系决定。
- 当前存发苗间库存不足时，按关联排列顺序继续分配至下一个存发苗间。
- 不允许产生负库存。
- 对应存发苗间库存 = 原库存数量 - 本存发苗间发货出库数。
- 其他入库、出库操作属于一期内容，本期不纳入库存计算。

上述规则描述业务口径，不等同于已确认的接口字段、数据库字段或页面字段。

## 8. 系统化边界候选

### 等价类与边界值

- 库存数量：正数、零、计算后不得为负数。
- 原库存数量：足够、不足、为空或未加载。
- 本存发苗间发货出库数：零、部分出库、全部出库、超过原库存的异常数据。
- 存发苗间关联：单个关联、多个按顺序关联、无关联。
- 查询结果：有数据、无数据、加载失败。
- 查询条件：默认条件、单条件、多条件、无匹配。
- 菜单权限：有菜单权限、无菜单权限；查询权限和数据权限属于一期内容，本期不考虑。

### 决策表维度

- 是否存在有效存发苗间关联。
- 当前库存是否足够。
- 是否需要继续分配到下一个存发苗间。
- 原库存与本存发苗间发货出库数是否可计算。
- 查询是否成功。
- 是否拥有菜单和查询权限。

### 状态转换候选

```text
页面进入 → 默认查询状态
查询条件设置 → 查询结果
有结果 → 库存展示
无结果/加载失败 → 空状态或错误表现
库存不足 → 关联存发苗间顺序分配
页面刷新 → 重新加载库存结果
```

| 参数 | 候选值 |
| --- | --- |
| `HatcheryState` | `Available`、`Unavailable`、`NotProvided` |

| `CalculatedInventory` | `Positive`、`Zero`、`NegativeCandidate`、`NotCalculated` |
| `AllocationState` | `SingleStorage`、`ContinueNextStorage`、`NoAllocation`、`NotProvided` |
