# REQ-PC-041 雏苗发货列表与筛选需求分析

## 1. 分析结论

REQ-PC-041 对应需求说明书中的 `REQ-001 雏苗发货列表与筛选`，属于 `计划管理 / 雏苗发货`，禅道模块对齐为二期 PC 雏苗发货，模块 ID 为 711。

本需求的核心是：展示排程计划形成的雏苗发货单，按日期、栋舍、品种和发货单号/孵化计划号进行组合查询，通过状态卡切换查看不同状态，并同步刷新状态统计、列表和分页；同时提供满足条件的发货入口、明细入口和导出配置入口。

真实页面路由已确认但仍在开发中，本次不访问。本次分析以页面功能测试为主，不开展接口测试、接口断言或接口契约验证；接口结果触发的页面可见表现仍作为功能边界记录。

## 5. 业务规则与数据口径

1. 查询默认使用当天计划发货日期；重置恢复当天、全部状态、全部栋舍、全部品种和空关键字。
2. 状态值为全部、待发货、发货中、已发货、已签收，仅通过状态卡切换；最新需求不再提供状态下拉筛选。栋舍和品种选项来自基础数据。
3. 关键字同时匹配发货单号和孵化计划号，支持模糊匹配；长度不设业务上限，200 字以内不得报错。
4. 日期格式为 `YYYY-MM-DD`，例如 `2026-03-13`；前端没有可输入非法日期的方式，接口传入非法日期时由后台校验不通过。
5. 状态统计按当前已应用的日期、栋舍、品种和关键字计算，不把当前状态卡再次作为统计条件叠加；数量为零时仍展示状态卡。
6. 实际可发数来自关联上孵计划的实际出雏总数；未达到已出雏的计划按零处理。
7. 已发货数为当前发货单下发货记录数量总和；待发货数为实际可发数减已发货数。
8. 发货进度为已发货数/实际可发数；实际可发数为零时显示 0%。
9. 查询后刷新统计、列表和分页并回到第一页；分页切换保留当前已应用筛选条件。
10. 列表按计划发货日期升序排序；日期相同按发货单号升序排序，状态不参与排序。
11. 发货入口按原子分支独立判定：已到日期+待发货显示可用入口；已到日期+发货中显示可用入口；已发货不显示可用入口；已签收不显示可用入口；未来日期不显示可用入口。实际可发数为零时的入口口径待确认，不得与正常可发分支合并。
12. 无结果、接口超时、基础数据加载失败和权限不足时不展示数据；权限不足提示“暂无操作权限”。
13. 平台使用菜单权限-接口权限权限树配置角色权限，不写死角色。导出依赖导出接口权限，无权限时提示“没有操作权限”；发货和明细按钮无独立权限要求，进入后无数据权限时展示暂无数据。
14. 导出按当前筛选结果导出，导出权限沿用平台导出接口权限。
15. 查询、状态卡切换和分页只读，不得修改原始发货单数据。


## 9. 系统性边界候选

### 等价类与边界值

- 日期：默认当天、有效单日、有效跨日、结束早于开始、无匹配日期。
- 状态卡：全部、待发货、发货中、已发货、已签收；无状态下拉筛选。
- 栋舍/品种：全部、有效基础数据选项、无匹配组合。
- 关键字：空、完整发货单号、完整孵化计划号、部分匹配、无匹配、200 字以内、超过 200 字。
- 结果集：一页内、多页、空结果。
- 数值：实际可发数为零、已发货数为零、待发货数为零、状态统计数量为零。
- 分页：第一页、最后一页、越界页码。

### 决策表维度

以计划日期是否达到、订单状态、实际可发数是否大于零、是否存在发货记录、是否已收到签收结果和是否有匹配结果作为决策维度，推导发货入口、明细入口、状态聚合和空状态展示规则。

### 状态转换维度

覆盖默认列表、查询结果、重置结果、状态卡结果、后续分页、导出配置弹窗及关闭/取消返回列表。

### PICT 参数/约束候选

| 参数 | 候选取值 |
| --- | --- |
| `PlanDate` | Today、Earlier、Later、ValidMultiDay、InvalidEndBeforeStart、NoMatch |
| `Status` | All、Pending、Shipping、Shipped、Signed |
| `House` | All、ValidBaseData、NoMatch |
| `Breed` | All、ValidBaseData、NoMatch |
| `Keyword` | Empty、ShipmentOrderMatch、HatchPlanMatch、PartialMatch、NoMatch、LengthLimitToConfirm |
| `ResultSet` | SinglePage、MultiplePages、Empty |
| `AvailableData` | ActualAvailableZero、ActualAvailablePositive、ShippedZero、PendingZero |

关键约束包括：结束日期不得早于开始日期；多页结果必须保留筛选条件；空关键字不应缩小结果集；实际可发数为零时进度为 0% 且不得产生正的待发货数；未来日期不得显示可执行发货入口。以上为分析候选，不是测试用例，也未生成 PICT 测试集。

| `CV-041-08` | 栋舍、品种筛选项来自基础数据全量选项 | 字段来源/等价类 | `blocked` |
| `CV-041-09` | 状态标签文字、颜色、样式存在差异且对应状态 | 视觉状态矩阵 | `blocked` |
| `CV-041-10` | 导出文件生成和下载由 `REQ-PC-044` 承接 | 范围追溯 | `out_of_scope_with_owner` |

生成器必须以 `coverage_id -> case_id[]` 建立集合映射；覆盖目标没有用例映射且未标记为 `blocked` 或 `out_of_scope_with_owner` 时，结果为 `missing_design`，不得完成交接。证据不足时保留 `blocked`，不得改写为已验证。

## 11. 覆盖账本追溯契约

本需求采用 `coverage-ledger-v2`。覆盖目标必须沿着“需求目标 → 页面板块 → 测试计划项 → 原子测试目的 → 测试用例”逐级追溯；生成器和评审器均执行集合校验：

- 分析覆盖目标必须全部出现在测试用例的 `coverage_ids` 中；
- 测试计划范围项必须至少关联一个原子测试目的和一个测试用例；
- 每个测试用例必须引用当前需求的合法 `coverage_id`，不得产生孤立用例；
- `blocked` 只能表示证据、数据、权限或环境不足，仍必须保留设计用例；无用例的目标必须标记 `missing_design` 并阻断交接；
- `out_of_scope_with_owner` 必须记录责任需求，不能用来掩盖本需求缺失。

页面覆盖按三层执行：`L1` 验证板块出现，`L2` 验证字段/列/标签展示，`L3` 验证字段来源、格式、计算、跨系统一致性或视觉差异。`page.json`、历史原型状态和 `sortable=false` 只能作为证据或待确认依据，不能直接替代业务断言。

| 页面板块 | 状态证据 | 层级 | 目标 |
| --- | --- | --- | --- |
| 筛选区 | `st-default`、`st-filter-keyword` | L1/L2/L3 | `CV-041-08`及组合筛选 |
| 状态统计区 | `st-default`、`st-stat-pending`、`st-filter-keyword` | L1/L2/L3 | `CV-041-01`、`CV-041-07`、`CV-041-09` |
| 发货单列表 | `st-default`、`st-filter-keyword`、`st-pagination-page2` | L1/L2/L3 | `CV-041-02`至`CV-041-07`、`CV-041-09` |
| 导出配置弹窗 | `st-export-dialog` | L1/L2 | `CV-041-10`，责任边界为 `REQ-PC-044` |

新增覆盖用例应优先标记为 `blocked` 而不是删除，待真实环境、数据和权限准备后执行；当前 `case_ids`、`planned_item_ids` 与 `atomic_purpose_ids` 以 YAML 分析产物为准。

## 12. 自动化定位边界规划

按 `qa-playwright-py-writer` 规则，定位优先级为：

1. `get_by_role`：查询、重置、状态统计、导出、弹窗按钮。
2. `get_by_placeholder`：关键字输入框。
3. `get_by_label` 或筛选区域内作用域定位：日期、状态、栋舍、品种。
4. 唯一标题或菜单文本：页面标题、面包屑和菜单。
5. 仅在语义定位不可用时使用作用域 CSS。

日期控件为 antd 分段输入，自动化不得直接假定字符串填充格式；应使用控件交互和可观察状态等待。重复行按钮必须使用行作用域定位。自动化规划使用可视浏览器 `headless=False`，不使用硬编码凭据或固定等待。

## 11. 风险、依赖与待确认

主要风险：原型为 mock 数据，无法代表真实页面数据；重复行按钮缺少稳定唯一定位器；统计、列表和状态聚合可能口径不一致；页面功能测试所需的数据和权限配置尚未准备；日期分段输入容易被不当填值破坏。

主要依赖：排程计划、上孵计划、栋舍/品种基础数据、商品禽养殖端签收结果及 REQ-PC-044 导出组件。

测试计划阶段仅需准备页面功能测试所需的授权测试数据、页面权限配置和原型/最新需求差异处理规则，不扩展为接口测试。
