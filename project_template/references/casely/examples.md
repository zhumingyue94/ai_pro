# Casely 标准用例示例

> 以下示例来自种禽孵化管理系统中已确认的测试用例及评审记录，仅用于演示标题、前置条件、步骤和预期的写法。
> 产品、菜单、页面、字段、状态、数据和用例编号均为业务示例，不是其他项目可直接复用的事实；生成新项目用例时必须替换为当前项目已确认内容。
> 示例只作为风格参考；新增用例仍需遵循 `test_style_guide.md` 及当前项目 YAML/Markdown 结构契约。

## 示例一：到期且待发货行按业务键展示可用发货入口

### TC-PC-041-067

**标题**: 到期且待发货行按业务键展示可用发货入口

**前置条件**:
- 测试环境已准备计划发货日期不晚于当前业务日期、状态为待发货且实际可发数大于0的授权发货单

**步骤**:
1. 使用具备相应权限的测试账号登录系统
   - 预期：登录成功，进入系统门户或应用入口页
2. 在应用门户选择「种禽孵化管理系统」，展开「计划管理」并点击「雏苗发货」
   - 预期：进入「雏苗发货」列表页，页面标题或内容区显示「雏苗发货」
3. 查看目标发货单行的操作列
   - 预期：目标行展示可点击且未置灰的发货入口

## 示例四：品种下拉展示有效及停用品种并可查询历史记录

### TC-PC-041-005

**标题**: 品种下拉展示有效及停用品种并可查询历史记录

**前置条件**:
- 测试账号具备「种禽孵化管理系统」应用权限和「计划管理 > 雏苗发货」菜单权限
- 测试账号具备雏苗发货列表查询、筛选和状态统计权限
- 测试环境已提供当前租户下品种基础数据的全量有效及停用品种清单，并准备至少一条历史发货记录关联停用品种作为核对依据

**步骤**:
1. 使用具备相应权限的测试账号登录系统
   - 预期：登录成功，进入系统门户或应用入口页
2. 在应用门户选择「种禽孵化管理系统」，展开「计划管理」并点击「雏苗发货」
   - 预期：进入「雏苗发货」列表页，页面标题或内容区显示「雏苗发货」
3. 点击查询条件区的「品种」下拉，展开选项列表
   - 预期：选项列表第一项为「全部」，其余各项与当前租户品种基础数据中的有效及停用品种逐一对应，无缺失项、无重复项
4. 选择停用品种并查询
   - 预期：列表显示与该停用品种关联的历史发货记录

## 示例五：同一并发数据基线下分步回读提交结果

### TC-PC-042-028（结构示例）

**标题**: 并发提交合计不超最新剩余数成功处理

**前置条件**:
- 页面 A 与页面 B 已进入同一发货计划的发货模式；
- 测试数据已定义两页面合计提交量不超过最新剩余数 R

**步骤**:
1. 在页面 A 与页面 B 按测试数据录入位置数量，并分别提交
   - 预期：两个页面均完成提交动作
2. 回读同一发货计划的最新剩余数和发货记录
   - 预期：最终剩余数等于 R 减去成功提交数量，业务记录数量与成功提交数量一致

> 说明：两个步骤共享同一数据基线、同一并发提交业务结果，因此保留在同一个用例中；如果改为不同数量条件或互斥业务结果，则应拆分为不同用例。

## 示例六：查询无匹配结果时明确展示空态且保留发货单基础信息

### TC-PC-042-034

**标题**: 查询无匹配结果时明确展示空态且保留发货单基础信息

**前置条件**:
- 已准备与本场景匹配的测试账号和授权脱敏测试数据
- 存在关联计划；筛选条件无匹配

**步骤**:
1. 使用具备相应权限的测试账号登录系统
   - 预期：登录成功，进入系统门户或应用入口页
2. 在应用门户选择「种禽孵化管理系统」，展开「计划管理」并点击「雏苗发货」
   - 预期：进入「雏苗发货」列表页，页面标题或内容区显示「雏苗发货」
3. 在计划号关键字搜索框输入不存在的计划号并按Enter
   - 预期：表格显示“暂无数据”，页面不显示其他计划记录；发货单的基础信息仍显示原来的内容
4. 点击计划号关键字搜索框右侧的内部查询按钮
   - 预期：按当前不存在的计划号执行查询，表格仍显示“暂无数据”
5. 点击计划号关键字搜索框内的“×”清空关键字
   - 预期：清空后立即恢复全部有效计划，并默认选中第一条有效计划

> 说明：空态文案、未显示的记录范围和保留的基础信息必须直接写明，避免使用“无误显示”“保持不变”等执行人无法准确判断的概括性表述。

## 示例七：发货数量为1时通过校验并允许确认提交

### TC-APP-022-018（结构示例）

**标题**: 发货数量为1时通过校验并允许确认提交

**前置条件**:
- 已登录具备发货执行权限的测试账号，并进入「发货执行」页；
- 已准备待分配数量大于1且库存充足的上孵计划。

**步骤**:
1. 点击目标上孵计划卡片的「发货」按钮
   - 预期：弹出标题为「确认发货」的弹窗。
2. 填写有效列和层，在「发货数量」输入1并点击「确认提交」
   - 预期：发货数量为1时通过数量校验，「确认提交」按钮保持可用，页面不显示数量非法或超出可发数量提示。

> 说明：边界值用例必须同时写明输入值、校验结果、可操作控件状态和排除性提示；不得用“放行”“按规则通过”“正常提交”等词概括系统表现。

## 示例七：同一数据基线下连续回读自动出库关联字段

### TC-APP-022-201（结构示例）

**标题**: 同一次发货后自动出库记录关联字段一致

**前置条件**:
- 已准备同一条可成功发货的计划、关联养殖客户和园区；
- 已确定具名授权操作人，并可记录发货提交成功时间。

**步骤**:
1. 由指定操作人完成同一条计划的发货，并记录提交成功时间
   - 预期：发货提交成功，生成唯一可定位的自动出库记录。
2. 查看该次发货生成的自动出库记录
   - 预期：养殖客户字段与计划关联养殖客户一致，园区字段与计划关联园区一致。
3. 回读该自动出库记录的操作人和操作时间字段
   - 预期：操作人字段与实际提交发货的授权操作人一致，操作时间字段与发货提交成功时间一致。

> 说明：51280~51283 共用同一计划、同一发货单和同一自动出库记录；不同字段作为连续回读预期保留在同一个用例中。
