# Casely 公共测试用例参考资料

## 目录用途

本目录保存可供 `projects/` 下各项目复用的测试用例写法参考，重点约束以下内容：

- 标题
- 前置条件
- 步骤
- 步骤预期

这些文件是仓库级公共参考资料，不替代各项目的测试用例 Schema、Markdown 渲染器、校验器、评审规则或业务事实。`examples.md` 中的产品、菜单、字段、状态和数据均为孵化管理系统示例，不代表其他项目的通用业务契约。

项目引用路径：从任一 `projects/<项目>/...` 目录按实际层级回溯至仓库根目录，再进入 `references/casely/`；例如从 `projects/biopark_breeding/phase-2/reference/casely/` 访问本目录可使用 `../../../../../references/casely/`。

## 文件说明

| 文件 | 用途 | 优先级 |
| --- | --- | --- |
| `test_style_guide.md` | 抽象并固化标题、前置条件、步骤和预期的写作规则 | 首要风格依据 |
| `examples.md` | 保存经过确认的完整用例示例，展示规则的实际用法 | 示例依据 |
| `../../.agents/references/testcase-markdown.template.md` | 规定 Markdown 交付结构和扩展字段 | 结构依据 |
| `../../.agents/references/testcase-yaml.template.yaml` | 规定 YAML 字段及结构化映射 | 数据依据 |
| `examples.md` | 保存已确认的业务示例，仅展示写法，不提供公共业务事实 | 示例依据 |

## Casely 使用顺序

后续生成或审阅用例时，按以下顺序读取：

1. 读取 `test_style_guide.md`，确定四个核心字段的写作规则。
2. 读取 `examples.md`，仅对照示例中的句式、步骤/预期格式；将其中业务术语替换为当前项目事实。
3. 读取 `../../.agents/references/testcase-markdown.template.md` 和 `../../.agents/references/testcase-yaml.template.yaml`，遵循公共交付结构和字段映射。
4. 生成 YAML 用例明细，并确保 `title`、`preconditions`、`steps[].action`、`steps[].expected` 与风格规则一致。
5. 生成前扫描 `steps[].action`，禁止使用“执行本用例的单一业务操作”等占位语；确认每个动作包含操作对象和动作内容。
6. 按现有流程生成或校验 Markdown；不要在 Markdown 中维护与 YAML 不一致的事实数据。
7. 生成前同时扫描标题、前置条件、步骤动作和步骤预期，禁止出现对执行人不可用的外部设计工具名称（包括“蓝湖”和大小写不敏感的 `lanhu`）；如需引用页面依据，改写为正式页面字段/控件基线或可观察页面规则。
8. 生成后同时扫描 YAML 与 Markdown，确认占位语和“蓝湖/lanhu”业务字段为 0，并逐条比对用例编号、标题、前置条件、步骤动作和步骤预期。
9. 生成前检查标题、前置条件、步骤和预期是否直接写出公式、字段、文案、状态或边界；禁止使用“按已确认规则”“页面定义”“页面约定”“按规则”“正常显示”“保持一致”等不可执行描述。规则未确认时必须明确标记具体阻塞对象和不判定范围。

## 维护规则

- 新增一条已确认的调整示例时，先更新 `examples.md`，再根据稳定的共性规则更新 `test_style_guide.md`。
- 只把已经确认、可复用的写法加入规范；一次性的业务内容不要抽象成通用规则。
- 当同一原预期同时覆盖展示内容和选择/查询后的业务结果时，示例应分别展示两个连续步骤，避免把后续操作结果写入前一步预期。
- 同一套数据基线下，同一动作或连续动作链产生的多个同一业务结果，可以保留在同一个用例中；应按动作、结果回读和关联校验拆成多个连续步骤，不得仅因预期包含多个关联核对点就新增用例。
- 只有不同数据基线、互斥状态/条件、不同业务对象或不同业务结果才必须拆分为不同用例；步骤拆分不等于用例拆分。
- 修改项目菜单、页面或业务术语时，同时检查 `examples.md` 和 `test_style_guide.md` 中的术语是否仍然准确。
- 如果规则与现有模板或 Schema 冲突，以项目现有结构契约为准，并单独评估是否需要修改生成流程。
- 不在本目录保存账号、密码、令牌、真实个人信息或自动化定位器。
- 本目录作为参考资料使用，不改变 `04_testcases`、`05_case_review`、`06_zentao_sync` 和 `07_ui_automation` 的输出路径及文件命名。

## 与现有流程的关系

```text
用例修改.md
    ├── test_style_guide.md  （抽象写法规则）
    └── examples.md          （保存标准示例）
             ↓
       后续 Casely 用例生成
             ↓
  现有 YAML/Markdown 模板与校验流程
             ↓
          04_testcases
```

当前新增资料不会自动改变生成流程；它们被定位为项目级风格参考。若后续要强制生成代理读取这些文件，需要再将路径显式加入相应 Skill 或项目配置，并评估与既有规则的优先级。
