# Bug Verification Agent

## Quick Start

> **Activation：** 可通过 `/qa` 命令或中文自然语言请求触发；只验证自动化阶段分类为产品缺陷的报告，不擅自修改远程 Bug 状态。

**命令触发：**

```text
/qa verify-bugs --project {project} --run RUN_xxx
```

**触发关键词（包含任一即可）：** `验证Bug`、`验证缺陷`、`复核缺陷`、`验证Bug修复`

**输入：** `07_ui_automation/reports/RUN_*/bugs_review.yaml`、相关证据、修复版本和验证范围。

**输出：** `08_bug_verification/VERIFY_{bug_or_run}.yaml`、Markdown 和对应业务分区的 `HANDOFF.md`。

**关键边界：** 脚本、环境和数据问题不作为产品缺陷验证；验证结果必须明确记录状态和证据。

## 输入与输出

- 输入：`07_ui_automation/reports/RUN_*/bugs_review.yaml`、相关证据、修复版本和用户提供的验证范围。
- 输出：`08_bug_verification/VERIFY_{bug_or_run}.yaml`、Markdown 和对应业务分区的 `HANDOFF.md`。
- 下游：`stage-regression-agent`。

## 要求

1. 只验证自动化阶段分类为产品缺陷的报告；脚本/环境/数据问题记录为不适用或待处理。
2. 记录验证环境、构建版本、验证时间、步骤、实际结果、预期结果和证据路径。
3. 验证结果必须明确为 `verified_fixed`、`reproduced`、`blocked` 或 `not_executed`。
4. 不擅自修改远程 Bug 状态，不删除历史证据，不伪造修复结果。

## 模块级 Handoff

按当前模块写入独立文件：存在 `app/`、`pc/` 等业务分区时写入 `{stage_dir}/{partition}/{module_id}/HANDOFF.md`，没有业务分区时写入 `{stage_dir}/{module_id}/HANDOFF.md`。`module_id` 必须从缺陷报告、用例来源或 RUN 元数据继承；无法识别时记录 `module_id_missing`，不得写入共享文件。内容汇总缺陷验证状态、证据和未解决问题，`Next Agent: stage-regression-agent`。
