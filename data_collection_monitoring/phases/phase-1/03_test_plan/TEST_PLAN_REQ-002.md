## 测试策略

- 采用黑盒、只读、风险优先策略；以 `REQ-002-001` 至 `REQ-002-014`、`REQ-002.yaml` 和 `page.json` product_category 页面为业务与页面边界。`partial` 状态下将不可观察或未完成契约记录为待确认/无法验证，不据此判失败。

- 使用判定表评估名称校验、同租户重名、停用关联保留与新产品选择阻断、有关联删除阻断、空字段显示、加载失败提示、保存中按钮状态、并发冲突和权限结果；新增/编辑/删除仅验证已采集表单或确认层的可观察只读状态。

- Pairwise/2-way 评估 `Auth`、`Permission`、`Name`、`Description`、`Status`、`Sort`、`Association`、`Action`、`Result` 组合。只读权限只能查询/重置/刷新；新增/编辑且名称为空或仅空白为校验失败；同租户重名按确认规则允许；删除且存在关联进入阻断；非法排序为校验失败。该模型用于计划设计，不生成或执行测试数据。
- Playwright Python/pytest-playwright 仅规划自动化范围：复用 `login_page.py` 和 `portal_navigation.py`，优先已登记 role/name、accessible label、confirmed data-testid、`page.json` element mapping、表格行上下文和可见文本；CSS 仅作为 `page.json` 已明确的最后手段。只规划进入页面、筛选/分页/列表只读、打开并取消表单或删除确认层、读取脱敏状态。
- Web 执行采用导航后等待可观察状态、操作前后页面状态比对和截图/日志证据；禁止固定等待、未确认定位器、提交保存删除停用、接口写入和绕过权限/安全验证。
