## 4. 已确认业务规则

### 4.1 职责边界

1. 本模块不配置告警对象；具体对象由数据监听模块配置。
2. 本模块不配置条件类型、表达式、多条件组合、采样窗口和数据缺失处理。
3. 本模块不配置阈值、单位、精度、滞回、持续时间和恢复条件。
4. 连续触发次数、频率限制、冷却、抑制、升级和启停生效时间由数据监听模块配置。
5. 规则版本由数据监听模块管理，历史告警关联触发时生效的规则版本。
6. 本模块配置不涉及产品、设备、分组、采集任务或字段，也不负责这些对象变化时的规则阻止、失效或迁移。
7. 本模块不提供沙箱、模拟数据或虚拟接收人，安全测试不属于本模块职责。

### 4.2 基础配置

1. 告警级别仅支持 `INFO`、`WARN`、`ERROR`，具体业务含义按页面现有定义执行。
2. 配置状态仅支持“开启”和“停用”；新增默认“开启”；状态切换即时生效；不存在草稿、发布中或失效等其他状态。
3. 配置名称必填，同一租户内允许重复，编辑时允许修改。长度、大小写、空格和特殊字符按系统默认规则处理。
4. 配置描述允许为空、不限制字数，使用单行文本输入框，不允许换行。
5. 告警级别默认不选中且为必填项。
6. 接收用户来自本系统用户管理，接收用户和接收类型均为必填并支持多选。
7. 接收类型支持短信、邮箱、站内信，不支持 Webhook、队列等其他类型。
8. 最新回答未单独确定通知模板、模板变量和渠道参数的页面归属；虽然确认项提到模板变量和送达结果，当前将其作为待补页面契约，不自行推断其实现位置。

### 4.3 引用、历史快照和保存校验

1. 告警配置被引用时不允许删除，但允许停用和编辑。
2. 停用后已有监听规则继续使用旧配置。
3. 历史告警保留触发时的告警配置快照。
4. 仅校验告警级别、接收用户、接收类型等基础必填项；缺失时禁止保存，错误信息定位到具体字段并保留输入。
5. 不额外校验告警对象、条件、阈值及其组合关系。
6. 列表默认按创建时间倒序；筛选、分页和刷新后保持创建时间倒序。

### 4.4 公共交互规则

- 无权限提示“没有操作权限”；
- 默认每页 10 条；筛选回第一页；无结果显示“暂无数据”；
- 查询失败、超时、网络异常或权限不足显示失败提示且无页面重试入口；
- 重复提交只生效一次；处理中禁止重复操作；
- 不缓存，刷新或重新加载获取最新数据；
- 取消或关闭表单无需二次确认；
- 校验失败在字段旁提示并保留输入；保存失败保留输入；
- 删除为软删除且列表不显示；停用仍显示并可恢复；被引用时阻止相关操作；
- 不要求审计记录。

## 6. 角色、依赖和风险

### 角色

- **告警配置管理员**：维护名称、描述、级别、状态、接收用户和接收类型；
- **数据监听管理员**：维护告警对象、条件、阈值、触发和规则版本；
- **用户/通知管理员**：维护系统用户及通知渠道上下文；
- **只读用户**：查看授权配置，不执行变更。

应按角色和租户范围验证查看、查询、新增、编辑、删除、停用、启用及无权限提示。不得根据按钮、菜单或表单可见推断写权限，不得绕过权限。

### 依赖

上游依赖：`REQ-003` 产品管理、`REQ-005` 设备管理、`REQ-007` 数据监听、`REQ-009` 数据采集、用户管理以及登录/门户/权限/租户上下文。下游依赖：`REQ-011` 告警记录、短信/邮箱/站内信通知渠道。

依赖仅表示责任边界，不代表接口、通知送达或历史快照已经验证。

### 风险

- 错误接收用户或渠道可能向真实人员发送通知；只读观察，不保存、不触发、不发送；
- 被引用配置的删除/停用行为不符合规则，可能影响监听和历史快照；只规划证据，不执行写操作；
- 接收人、手机号、邮箱、模板变量或通知结果泄露；严格脱敏，不写入截图、日志、DOM、报告或下载文件；
- 模板变量和送达结果职责不清；记录待确认，不推断实现；
- 权限/租户边界不完整；记录阻塞，不绕过权限。

## 7. 系统性测试设计

### 7.1 等价类

- 配置名称：有效、空、非法字符、同租户重复；
- 描述：空、单行、换行；
- 告警级别：未选、`INFO`、`WARN`、`ERROR`；
- 配置状态：开启、停用；
- 接收用户：单选、多选、空、越权；
- 接收类型：短信、邮箱、站内信、不支持 Webhook/队列；
- 操作：查看、查询、新增、编辑、删除、启用、停用；
- 引用：未引用、已引用；
- 权限：完整、只读、拒绝、跨租户受限；
- 查询：有结果、无结果、失败。

### 7.2 边界候选

- 名称、描述：空、最小、最大、非法字符；当前确认不限制长度，但具体非法字符集待系统确认；
- 接收用户数量：空、1、最大、超限；上限待确认；
- 日期：空值、同日、开始晚于结束、跨月跨年；
- 分页：空、单条、10 条、末页、无结果。

### 7.3 判定表

| 条件 | 期望结果 |
|---|---|
| 级别、接收用户或接收类型缺失 | 字段提示错误，禁止保存并保留输入 |
| 配置未被引用并删除 | 允许执行软删除，列表不再显示；本阶段不执行 |
| 配置已被引用并删除 | 阻止删除并显示引用/权限反馈；具体提示待页面证据 |
| 配置已被引用并停用或编辑 | 允许；已有监听规则继续使用旧配置 |
| 状态开启/停用 | 切换即时生效；无草稿、发布中或失效状态 |
| 接收类型为短信/邮箱/站内信 | 允许选择；具体字段页面证据待补 |
| 接收类型为 Webhook/队列 | 不支持，不能作为有效配置 |
| 默认/筛选/分页/刷新 | 均按创建时间倒序；筛选回第一页 |

### 7.4 状态迁移

```text
未认证 -> 登录 -> 门户 -> 告警配置默认态
默认态 -> 新增/编辑 -> 校验失败或保存成功
开启 <-> 停用（即时生效）
未引用/已引用 -> 删除允许或阻止
配置触发 -> 历史告警保存触发时配置快照（仅契约分析，不触发）
```

## 8. PICT 参数与约束候选

```text
Permission: full_control, read_only, denied, cross_tenant_limited
Tenant: same, other, missing
RequiredFields: complete, missing_name, missing_severity, missing_receiver, missing_type
Severity: INFO, WARN, ERROR, unselected
Status: enabled, disabled
ReceiverCount: zero, one, multiple, over_limit
ReceiveType: SMS, Email, InApp, Webhook, Queue
Reference: unreferenced, referenced
Action: view, query, add, edit, delete, enable, disable
Result: visible, validation_error, permission_error, saved, blocked, no_data

IF [Permission] IN {read_only, denied, cross_tenant_limited} THEN protected write action is permission_error;
IF [RequiredFields] != complete THEN [Result] = validation_error;
IF [Severity] = unselected OR [ReceiverCount] = zero THEN [Result] = validation_error;
IF [ReceiveType] IN {Webhook, Queue} THEN [Result] = validation_error;
IF [Reference] = referenced AND [Action] = delete THEN [Result] = blocked;
IF [Status] = disabled AND [Action] = disable THEN [Result] = visible;
IF [Tenant] = other THEN protected data/action is permission_error;
```

该模型用于 pairwise 页面验证设计，不构成通知接口、规则引擎或真实送达结论。
