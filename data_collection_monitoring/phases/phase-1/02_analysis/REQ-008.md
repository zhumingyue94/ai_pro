## 4. 已确认业务规则

### 4.1 目标字段

目标名称、目标类型、请求地址、请求方法和目标状态为必填项。目标描述、请求头、请求参数和请求体为非必填项。三种类型截图进一步确认：HTTP 还包含协议选择/地址输入、请求头、请求参数和请求体；MQTT 包含服务地址、用户名、密码、客户端 ID 和主题；RocketMQ 包含 `NameServer`、`AccessKey`、`SecretKey`、消费组、主题和标签。编辑表单字段与新增表单一致，三种表单均提供确定/取消操作，目标状态截图默认开启。

具体名称、地址、主题、路径、消息体长度上限、空白和特殊字符处理、编辑可修改范围、提交反馈、重复提交、列表回显和稳定定位器未由截图证明，不自行假定。

### 4.2 类型和协议

支持 HTTP、MQTT 和 RocketMQ。

- HTTP 支持配置请求体；
- MQTT 和 RocketMQ 不设置请求体，仅配置主题；
- 消息内容、字段映射、编码方式、必填字段和消息版本按目标类型的默认配置规则处理；
- QoS、状态码、返回码及断开重连按对应协议默认规则处理；
- RocketMQ 表单填写和提交属于当前需求范围，具体字段差异必须按实际页面记录。

### 4.3 超时、发送和重复消息

连接和发送超时按系统默认值。发生超时后标记为失败或超时状态，系统按默认策略自动重连。

消息按产生顺序逐条发送，重复消息按事件唯一标识处理。不启用批量发送和限流，发送结果按接收方响应确认。

乱序消息的具体处理未在最新确认中明确，不应推断为排序、丢弃或补偿。

### 4.4 失败、死信和人工重发

推送失败按类型记录，不自动重试，失败消息直接进入死信，并支持人工选择消息重新发送。重复发送按系统默认规则处理。

死信列表、失败详情、人工选择重发入口、重发确认和结果提示需要按实际页面记录；当前尚无完整 `page.json` 页面实体或独立权限定位器。

### 4.5 引用生命周期

推送配置停用后不能被新的监听规则或采集任务选择，但已有监听规则或采集任务继续使用原推送配置，不受停用影响。推送配置被使用时不允许删除。

```text
停用目标 -> 新监听/采集任务不可选择
已有引用 -> 继续使用原配置
被引用目标 -> 不允许删除
```

### 4.6 连接测试、脱敏和清理

不提供连接测试功能。连接测试由技术人员自行对接调通，不纳入本页面测试范围，不涉及测试消息、隔离目标、结果保存或失败清理。

推送地址按业务需要展示；证书、密钥、消息内容和返回内容中的敏感信息必须脱敏，不允许明文出现在日志和错误提示中。删除或替换敏感配置后必须清理旧值。

### 4.7 列表排序和公共规则

推送配置列表默认按创建时间倒序，最新创建的配置在前。筛选、分页和刷新后保持创建时间倒序。

本轮核心流程缺口复核确认：现有用例已覆盖停用目标的新引用阻止、已有引用继续使用和被引用删除阻断的设计方向；不重复创建这些分支。依据已确认的“停用仍显示并可恢复、删除为软删除且列表不显示、重复提交只生效一次、处理中禁止重复操作”和必填字段规则，新增用例仅覆盖以下尚未形成闭环的方向：停用后恢复及恢复后的新引用、必填字段提交失败、未引用目标删除后的列表/刷新回读、重复提交及处理中重复操作。上述用例均保持 `blocked`，不宣称页面或业务写操作已执行成功。

公共确认项还要求：

- 无权限提示“没有操作权限”；
- 默认每页 10 条；
- 筛选回第一页；
- 无结果显示“暂无数据”；
- 查询失败、超时、网络异常或权限不足显示失败提示，且无页面重试入口；
- 重复提交只生效一次；
- 处理中禁止重复操作；
- 不缓存，刷新或重新加载获取最新数据；
- 删除为软删除且列表不显示；
- 停用仍显示并可恢复；
- 被引用时阻止相关操作；
- 项目不要求审计记录。

## 7. 系统性测试设计

### 7.1 等价类和边界

- 目标字段：完整、分别缺失名称/类型/地址/方法/状态；
- 目标类型：HTTP、MQTT、RocketMQ；请求体或主题字段适用性；
- 目标状态：开启、关闭；停用后新引用禁止，已有引用继续；
- endpoint：合法、格式错误、不可达、超时；
- response：成功、客户端失败、服务端失败、超时、网络异常、拒绝；
- event：唯一、重复、延迟、乱序、突发；逐条发送、不批量、不限流；
- permission：可读、可写、拒绝、跨租户受限；
- 列表：有结果、无结果、查询失败、筛选回第一页、10 条分页边界。

边界候选包括名称、地址、主题、路径、消息体最大值减一/最大值/最大值加一（具体上限待确认），日期空值/同日/开始晚于结束/跨月跨年，以及空列表/单条/10 条/末页/无结果。

### 7.2 判定表

| 条件 | 期望结果 |
|---|---|
| 目标停用，新监听或采集任务选择 | 阻止选择 |
| 目标停用，已有监听或采集任务引用 | 继续使用原配置 |
| 目标被引用，执行删除 | 阻止删除 |
| HTTP 类型 | 可配置请求体 |
| MQTT 或 RocketMQ 类型 | 不配置请求体，仅配置主题 |
| 接收方响应成功 | 按响应确认发送结果 |
| 推送失败 | 按类型记录，直接进入死信，不自动重试 |
| 人工选择重发 | 按系统默认重复发送规则处理，并展示确认和结果反馈 |
| 默认/筛选/分页/刷新 | 均按创建时间倒序；筛选回第一页 |

### 7.3 状态迁移

```text
未认证 -> 登录 -> 门户 -> 数据推送默认态
默认态 -> 查询中 -> 有结果/无结果/失败
开启 -> 关闭 -> 新引用阻止/已有引用继续
事件到达 -> 逐条发送 -> 接收方响应/失败 -> 死信 -> 人工选择重发
```

## 8. PICT 候选模型

```text
Permission: full_readonly, write, denied, cross_tenant_limited
TargetType: HTTP, MQTT, RocketMQ
TargetState: enabled, disabled
RequiredFields: complete, missing_name, missing_type, missing_address, missing_method, missing_status
Endpoint: valid, malformed, unreachable, timeout
Event: unique, duplicate, delayed, out_of_order, burst
Response: success, client_error, server_error, timeout, network_error, reject
Retry: none, manual_resend
Result: visible, validation_failed, permission_failed, delivered, dead_letter, blocked

IF [TargetState] = disabled THEN new reference/delivery is blocked;
IF [RequiredFields] != complete THEN add/edit validation fails;
IF [Response] IN {server_error, timeout, network_error, reject} THEN result is dead_letter;
IF [Retry] = none THEN automatic retry is not expected;
IF [Permission] IN {denied, cross_tenant_limited} THEN protected action is permission_failed;
IF [TargetType] IN {MQTT, RocketMQ} THEN request body is not applicable;
```

该模型是候选 pairwise 设计，不代表已执行真实投递、失败制造、死信生成或接口验证。
