# 页面探索覆盖规范

## 目的

通过“组件覆盖矩阵 + 页面状态记录 + 人工完成检查”减少页面探索中遗漏 UI 组件、展开区域、弹窗字段和交互状态的问题。本规范是人工执行参考，不是自动化门禁，不设置覆盖率阈值、CI 阻断规则或强制完成条件。

## 探索范围

每个页面至少检查以下范围，并将实际结果记录到 `page.json`：

| 范围 | 检查内容 |
| --- | --- |
| 页面结构 | 路由、标题、菜单路径、页面尺寸、视口尺寸、滚动区域、面包屑 |
| 筛选与查询 | 文本输入、下拉、日期、级联、清除、查询、重置 |
| 列表与表格 | 表头、排序、列设置、分页、空数据、横向滚动、行操作 |
| 页面操作 | 新增、刷新、导入导出、批量操作、启停、查看 |
| 弹窗与抽屉 | 初始字段、默认值、必填、只读、校验、确认、取消 |
| 派生状态 | 展开/收起、Tab、下拉面板、日期面板、树节点、二级弹窗 |
| 反馈状态 | 加载、成功、失败、确认提示、空数据、异常或权限限制 |

## 派生状态规则

发现以下控件时，不只记录控件入口，应记录触发前后发生变化的状态：

- 更多配置、展开/收起、折叠面板；
- Tab、下拉、日期选择器、级联选择器；
- 表头设置、树节点、抽屉、二级弹窗；
- 分页、排序、横向滚动等会改变可见数据的控件。

推荐流程：

```text
记录初始状态 → 操作控件 → 等待界面稳定 → 记录变化状态 → 关闭浮层或恢复页面
```

有新增字段时，应同步记录 `elements`、`forms.field_element_ids`、`interactions`、DOM 快照和截图证据。

## 状态命名

优先使用能表达页面变化的状态名称：

- `{page_id}_default`
- `{page_id}_{operation}_collapsed`
- `{page_id}_{operation}_expanded`
- `{page_id}_{operation}_validation_error`
- `{page_id}_{operation}_confirm`
- `{page_id}_{operation}_success`
- `{page_id}_{operation}_empty`
- `{page_id}_{operation}_blocked`

如果初始弹窗状态已使用既有名称，应保持兼容，并在新增状态中明确展开或变化内容。

## 表单字段记录

每个实际可见或可操作字段应记录：

- `element_id`、`kind`、`tag`、`role`、`label`；
- 可见、启用、必填、只读、选中和值状态；
- 稳定定位器候选及可信度；
- 所属表单的 `field_element_ids`；
- 展开后出现的字段不得只写在说明文本中。

新增、编辑和新增子对象等相似弹窗应分别核对，不直接假设字段和只读状态相同。

## 操作边界

### 无副作用探索

可直接进行：展开/收起、切换 Tab、打开下拉或日期面板、打开详情、翻页、横向滚动、打开确认弹窗、输入后清除。

### 有副作用操作

新增、编辑、删除、启停、批量提交和启动采集等操作，必须在日志中记录：

- 是否实际提交；
- 提交前后的状态；
- 测试数据责任边界；
- 清理方式和清理结果。

未获授权或无法清理时，记录 `blocked`、`partial` 或 `input_missing`，不得凭猜测补齐页面事实。

## 证据要求

重要页面状态应保存原始比例截图和脱敏 DOM 快照，并在 `page.json` 的 `evidence` 中引用。截图前读取实际内容尺寸；不得使用 CSS 缩放压缩页面。浮层逐一打开、截图、关闭，避免互相遮挡。日志不得包含账号、密码、Token、Cookie、认证状态、内部地址或未经授权的业务隐私数据。

## 完成前人工复核

探索结束前人工核对：

1. 所有页面级、组件级和弹窗级范围是否已检查；
2. 每个会改变界面的控件是否有前后状态记录；
3. 展开字段是否进入 `elements` 和表单字段列表；
4. 重要状态是否有截图、DOM 和日志引用；
5. 业务变更是否记录提交及清理边界；
6. 未引用证据是否已清理；
7. `page.json` 是否通过 `.agents/references/page.schema.json` 格式校验。

上述复核是人工参考，不作为自动化页面探索门禁。
