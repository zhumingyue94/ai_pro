## 4. 已确认业务规则

### 4.1 任务名称和配置字段

1. 任务名称由系统自动生成的前缀与新增弹窗中“任务标识”填写内容拼接而成；自动生成的前缀不可修改，任务标识由用户填写。
2. 数据采集仅用于创建定时任务，不区分轮询、订阅或事件触发。
3. 新增弹窗包含任务标识、Cron 表达式、脚本、重启策略和内存限制。
4. 任务标识、Cron 表达式和脚本必填；重启策略和内存限制可选。
5. 页面没有采集协议字段，因此不涉及采集协议、版本及其和插件、设备、产品的兼容关系。
6. 页面不配置设备范围、设备选择、批量选择、分组选择或字段映射。
7. 采集字段、数据类型、单位、质量码和数据转换由用户提供的脚本处理；脚本格式错误时任务执行失败。

### 4.2 调度、状态和执行

1. 按新增或编辑弹窗中的 Cron 表达式执行定时任务，时区按系统默认规则。
2. 批量大小、并发、互斥、错过调度及重复触发按系统默认规则；任务重复触发时按重启策略处理。
3. 需求确认的业务状态只有：已创建、运行中、已停止。
4. 任务创建后为已创建；启动后为运行中；停止后为已停止；已停止任务可以再次启动，也可以删除。
5. 不涉及暂停、恢复和超时状态。
6. 重启策略包括：`no`（不自动重启）、`on-failure`（异常退出时重启）、`always`（总是重启）、`unless-stopped`（除非手动停止）。
7. 设备离线、插件异常、脚本格式错误及部分成功按所选重启策略处理；重试等待、断点续采、失败状态展示和人工重跑范围按对应重启策略及系统默认规则处理。

### 4.3 页面状态差异

`page.json` 观察到的任务状态还包括已暂停、重启中、删除中和异常。这些状态没有在当前 REQ-009 业务确认中定义，因此只作为页面/需求差异记录，不直接升级为正式业务状态，也不推断其状态转换或操作权限。

### 4.4 引用、脱敏和排序

1. 插件、设备或产品发生变化时，不影响已有采集任务配置，定时任务继续按原配置执行。
2. 如果引用对象变化导致无法执行，则本次执行失败，失败处理按任务设置的重启策略执行。
3. 采集值和设备标识按业务需要展示。
4. 认证信息、外部地址、消息和返回内容中的敏感信息必须脱敏，敏感信息不得在日志中明文保存。
5. 采集任务列表默认按创建时间倒序排列；筛选、分页和刷新后保持创建时间倒序。

### 4.5 公共交互规则

- 无权限时提示“没有操作权限”；页面和按钮无单独权限；
- 默认每页 10 条；筛选回第一页；无结果显示“暂无数据”；
- 查询失败、超时、网络异常或权限不足显示失败提示且无页面重试入口；
- 重复提交只生效一次；处理中禁用相关操作；
- 不缓存；刷新或重新加载获取最新数据；
- 取消或关闭表单直接关闭，不需二次确认；
- 校验失败在对应字段旁提示并保留输入；保存失败保留输入；
- 删除按软删除处理且列表不显示；停用仍显示并可恢复；被引用时阻止相关操作；
- 项目不要求审计记录。

## 7. 系统性测试设计

### 7.1 等价类

- 任务标识：合法、空、仅空白、超长、非法字符；
- Cron：合法、非法、系统默认时区；
- 脚本：合法、格式错误、缺失；
- 重启策略：`no`、`on-failure`、`always`、`unless-stopped`；
- 内存限制：未配置、已配置、最小、最大、超限候选；
- 任务状态：已创建、运行中、已停止；页面额外状态单独核实；
- 引用：未变化、变化但可用、失效；
- 执行：成功、部分成功、设备离线、插件异常、脚本错误、失败；
- 权限：完整控制、只读、拒绝、跨租户受限；
- 查询：有结果、无结果、失败、超时、网络异常。

### 7.2 边界值

- 任务标识、Cron、脚本和内存限制：空、最小、最大、超限；具体系统上限和默认值待确认；
- 状态：创建、启动、停止、再次启动、删除；暂停/恢复/超时按当前确认不适用；
- 分页：空、单条、10 条边界、末页、无结果；记录页面观察的 200 与公共默认 10 的差异；
- 筛选：精确匹配/模糊匹配、组合条件、筛选后回第一页，并遵循公共匹配规则。

### 7.3 判定表

| 条件 | 期望结果 |
|---|---|
| 任务标识、Cron 或脚本缺失/非法 | 对应字段校验失败，保留输入，不保存 |
| 已创建任务启动 | 进入运行中；确认层和异步完成反馈待页面证据 |
| 运行中任务停止 | 进入已停止；确认层和异步完成反馈待页面证据 |
| 已停止任务再次启动 | 重新进入运行中 |
| 已停止任务删除 | 执行软删除，列表不再显示；不执行真实操作 |
| 设备离线、插件异常、脚本错误或部分成功 | 按 `no`、`on-failure`、`always`、`unless-stopped` 处理；等待和最终提示待确认 |
| 引用对象变化但仍可用 | 继续使用原任务配置 |
| 引用失效 | 本次执行失败，并按重启策略处理 |
| 默认、筛选、分页、刷新 | 创建时间倒序；筛选回第一页；无结果显示“暂无数据” |

### 7.4 状态迁移

本轮补充的核心流程缺口：

- `TC-REQ-009-050` / `TC-REQ-009-051`：任务编辑保存成功、保存失败及配置回读；
- `TC-REQ-009-052` / `TC-REQ-009-053`：任务启动后的异步状态、执行结果回读及失败反馈；
- 不新增模块未确认存在的删除或其他控制功能用例。

```text
未认证 -> 登录 -> 门户 -> 数据采集默认态
默认态 -> 查询中 -> 有结果/暂无数据/失败
新建表单 -> 校验失败/保存成功/取消
已创建 -> 启动 -> 运行中 -> 停止 -> 已停止
已停止 -> 再次启动 -> 运行中
已停止 -> 删除
运行中 -> 设备离线/插件异常/脚本错误/部分成功 -> 按重启策略处理
引用变化 -> 原配置继续使用；引用失效 -> 本次执行失败 -> 按重启策略处理
```

```text

Schedule: cron_valid, cron_invalid, timezone_default

RestartPolicy: no, on_failure, always, unless_stopped
MemoryLimit: absent, configured, boundary_low, boundary_high, over_limit
TaskState: created, running, stopped
Reference: unchanged, changed_usable, invalid
Execution: success, partial_success, device_offline, plugin_error, script_error, failed
Result: visible, validation_error, permission_error, processing, succeeded, failed, blocked

IF [Auth] != valid THEN [Result] = permission_error;
IF [Permission] IN {read_only, denied, cross_tenant_limited} THEN protected write/control action is permission_error;
IF [TaskIdentifier] IN {empty, whitespace_only} THEN create/edit result is validation_error;
IF [Script] IN {missing, malformed} THEN [Result] IN {validation_error, failed};
IF [Schedule] = cron_invalid THEN [Result] = validation_error;
IF [Reference] = invalid THEN execution result is failed;
IF [Execution] IN {device_offline, plugin_error, script_error, partial_success} THEN [Result] IN {failed, processing} according to [RestartPolicy];
```
