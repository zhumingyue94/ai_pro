## 3. 最新确认业务规则



### 3.1 名称、备注和序列号



- 设备名称必填，同一租户或业务范围内唯一；编辑改名必须重新校验唯一性。

- 名称长度、空白和特殊字符按系统默认规则；不自行虚构具体长度或字符白名单。

- 备注非必填，可为空，支持换行、空白和常见特殊字符；REQ-005-016 已确认备注不限制字段长度。

- 页面没有“设备标识”字段；序列号由用户录入且允许修改。

- REQ-005-016 确认名称和序列号必填且唯一，限制非法字符但不限制字段长度；校验失败时错误定位到对应字段。



名称唯一性和序列号唯一性必须分别设计，不能因页面不存在设备标识字段而省略序列号验证。



### 3.2 产品和设备类型



- 设备类型属于产品属性，设备侧不单独维护。

- 新建设备必须选择产品，设备类型由所选产品带入，设备侧不可单独修改。

- 设备绑定产品后不可更换。

- 产品停用或删除后已有设备保留原产品绑定，但不得新增关联。

- 产品存在绑定设备时不允许删除；具体阻止提示和跨模块证据需要按实际页面记录。



### 3.3 设备状态与跨模块一致性



最终状态集合为：未激活、在线、离线。



- 未完成激活的设备保持未激活。

- 设备建立连接后为在线。

- 连接断开后立即为离线。

- 激活后可通过建立连接恢复在线。

- REQ-005-017 要求设备管理状态与插件管理“设备数”弹窗中对应设备状态一致。

- 状态事件来源、更新时间序列和页面可观察反馈仍需运行时证据，不纳入接口测试推断。



### 3.4 排序与上线时间



已确认：



- 新增/编辑支持设置“同级排序”。

- 设备列表按“排序”字段升序排列。

- REQ-005-018 另确认“上线时间”为最近一次上线时间，重新上线后更新，离线后保留。



因此“排序”和“上线时间”必须作为两个独立语义验证。上线时间的实际列、来源、用户时区、格式、并列排序和页面展示仍待确认，不能将排序字段当作上线时间。



### 3.5 父子设备



- 支持父设备、子设备和多级层级。

- 父子设备可属于不同产品类型。

- 通过编辑设备和修改上级设备实现绑定、解绑和移动。

- 不设置固定最大层级，以页面实际可创建层级为准。

- 禁止循环引用，移动后也不得形成循环。

- 父设备有子设备时不能直接删除，必须先处理子设备。



跨租户移动、移动失败回滚、最大实际深度和页面阻止提示仍需证据。



### 3.6 分组关系



- 一个设备可加入多个分组，支持批量加入。

- 重复加入不产生重复关系。

- 冲突项保留失败明细。

- 加入/移出后分组数量和可见范围立即更新。



页面分组选择、冲突明细、批量失败提示及整体回滚尚无 REQ-005 专属定位器。



### 3.7 业务引用与删除



设备引用包括产品、插件、采集任务及其他业务引用：



- 任一引用存在时禁止删除。

- 有引用时仍允许编辑和停用。

- 解除全部业务引用后才允许删除。

- 父设备有子设备时另受父子删除前置条件约束。



删除阻止不应连带禁止编辑或停用；页面应分别记录操作按钮状态和反馈。



### 3.8 批量操作



适用范围为批量删除和批量分组：



- 任一项失败，全部回滚。

- 显示失败明细和失败原因。

- 不自动重试；用户修正后重新发起整体批量操作。

- 不保留部分成功结果或残留关系。

- REQ-005-020 明确残留关系检查不属于本阶段功能测试范围。



本阶段只设计事务边界和页面证据，不执行真实批量写操作。



### 3.9 设备凭据



当前设备管理页面无设备凭据字段，本项不适用。不规划凭据显示、查看、轮换、失效或连接测试行为。

## 6. 角色、权限与依赖



角色候选：



- **设备查看人员**：在授权租户和业务范围内查看设备及关系。

- **设备管理员**：维护设备生命周期和父子关系。

- **分组管理员**：维护设备分组关系和批量分组。

- **产品管理员**：维护产品状态和设备可绑定范围。



公共权限规则要求菜单和接口权限由系统管理角色配置；不能从按钮可见性推断写权限。当前没有完整角色/租户矩阵，跨租户访问和批量操作权限保持待确认。



依赖模块为产品管理、设备分组、插件管理；业务链路还可能涉及数据采集、监听、推送、告警和其他引用。模块拆分中的依赖仅是范围顺序，不是已验证的接口事实。



## 7. 系统性测试设计



### 7.1 等价类和边界



- 名称：唯一、空、同作用域重复、非法字符、系统默认边界。

- 序列号：唯一、空、重复、非法字符、系统默认边界。

- 备注：空、空白、换行、常见特殊字符。

- 产品：可用、停用但已有绑定、删除但已有绑定、不可用于新增、缺失。

- 状态：未激活、在线、离线、断开、激活后重连。

- 层级：根、子、多级、跨产品类型、循环尝试、父有子。

- 分组：单组、多组、批量、重复关系、冲突。

- 引用：无引用、产品、插件、采集任务、其他、全部解除。

- 批量：全成功、单项失败、整体回滚、失败明细、整体重试。

- 权限：授权、未授权、跨租户。



### 7.2 判定表



| 条件 | 期望结果 |

|---|---|

| 名称/序列号为空、重复或唯一 | 空或重复拒绝；唯一允许；编辑重新校验并保留输入 |

| 产品可用、停用或删除 | 已有绑定保留；停用/删除产品不得新增关联；新建设备必须选择可用产品 |

| 未激活、连接、断开、重连 | 未激活保持未激活；连接在线；断开立即离线；重新连接恢复在线 |

| 父子关系和移动目标 | 允许多级及移动；不同产品类型可存在；循环移动拒绝 |

| 父设备有子设备 | 不允许直接删除，先处理子设备 |

| 业务引用存在 | 删除拒绝；编辑和停用允许 |

| 批量任一项失败 | 整体回滚、展示失败明细、用户整体重试，无部分结果 |

| 分组重复或冲突 | 重复关系不新增；冲突展示失败明细；关系变化后数量/可见范围更新 |



### 7.3 状态迁移



```text

未激活 -> 建立连接 -> 在线 -> 断开 -> 离线 -> 重新连接 -> 在线

根设备 -> 子设备 -> 多级层级 -> 解绑/移动

设备 -> 加入分组 -> 多分组 -> 移出分组

无引用 -> 存在引用 -> 删除拒绝 -> 解除全部引用 -> 删除允许

批量操作 -> 任一失败 -> 整体回滚 -> 修正原因 -> 整体重试

```



## 8. PICT 参数和约束候选



```text

Name: unique, empty, duplicate, invalid_default_rule

Serial: unique, empty, duplicate, invalid_default_rule

Product: active_available, inactive_existing_binding, deleted_existing_binding, unavailable_new, missing

Status: unactivated, online, offline, reconnect

Hierarchy: root, child, multi_level, different_product_type, cycle_attempt, parent_with_children

Group: single, multiple, batch, duplicate_relation, conflict

Reference: none, product, plugin, collection_task, other, all_cleared

BatchResult: success, one_failure, rollback, failure_detail, whole_retry

Permission: authorized, unauthorized, cross_tenant



IF [Hierarchy] = cycle_attempt THEN [BatchResult] = rollback;

IF [Reference] IN {product, plugin, collection_task, other} THEN [BatchResult] <> success;

IF [BatchResult] = one_failure THEN [BatchResult] = rollback;

IF [Permission] IN {unauthorized, cross_tenant} THEN [BatchResult] <> success;

```



以上是参数、取值和约束候选，不是已执行的组合。真实写操作、批量变更和接口测试均不执行。
