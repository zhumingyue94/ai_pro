# 页面探索覆盖规则

## 1. 适用范围

本规则适用于使用 `page.json` 整理真实页面探索结果的项目。执行页面探索前，先结合需求说明、模块拆分和可用原型确认探索范围；页面事实必须以实际页面探索结果为准，不得凭猜测补齐。

本规则是人工执行参考，不是自动化门禁：不设置覆盖率阈值，不新增覆盖率脚本、CI 阻断或强制完成条件。`page.schema.json` 仅用于校验清单结构，不代表页面功能覆盖已经完整。

本规则只约束采集作业质量：采集结果（包括未采集、部分采集、未登记页面或缺少定位器证据）不作为需求分析、测试计划、用例生成、用例评审、禅道同步、UI 执行或回归等任何下游阶段的门禁、阻塞或字段判断条件，只可作为普通参考资料。

## 2. 页面覆盖范围

每个页面至少人工检查并按真实结果记录以下范围：

| 范围 | 检查内容 |
| --- | --- |
| 页面结构 | 路由、标题、菜单路径、面包屑、页面尺寸、视口尺寸、滚动区域和横向溢出 |
| 筛选与查询 | 文本输入、下拉、级联、日期控件、清除、查询、重置和无结果状态 |
| 列表与表格 | 表头、排序、列设置、分页、空数据、横向滚动、行选择和行操作 |
| 页面操作 | 新增、刷新、导入导出、批量操作、启用停用、查看和返回 |
| 弹窗与抽屉 | 初始字段、默认值、必填、只读、禁用、校验、确认、取消和关闭行为 |
| 反馈状态 | 加载、成功、失败、确认提示、空数据、异常、权限限制和阻塞项 |

## 3. 派生状态和前后对比

以下控件不能只记录入口，必须检查触发前后的页面变化：

- 更多配置、展开/收起和折叠面板；
- Tab、下拉面板、日期选择器和级联选择器；
- 表头设置、树节点、抽屉和二级弹窗；
- 分页、排序、横向滚动等会改变可见数据或布局的控件。

推荐流程：

```text
记录初始状态 → 操作控件 → 等待界面稳定 → 记录变化状态 → 关闭浮层或恢复页面
```

对比时重点确认新增、隐藏或变化的输入框、下拉框、按钮、提示文本、可见性、禁用、只读、必填、选中状态及字段顺序。

如果产生新状态，应在 `page.json` 中单独记录状态，并同步更新 `elements`、`forms.field_element_ids`、`interactions` 以及对应 DOM、截图和日志证据。展开后出现的字段不得只写在说明文本中。

## 4. 状态命名和表单记录

优先使用能表达页面变化的状态名称：

- `{page_id}_default`
- `{page_id}_{operation}_collapsed`
- `{page_id}_{operation}_expanded`
- `{page_id}_{operation}_validation_error`
- `{page_id}_{operation}_confirm`
- `{page_id}_{operation}_success`
- `{page_id}_{operation}_empty`
- `{page_id}_{operation}_blocked`

只记录实际存在或已真实确认的状态；无法探索的状态应记录 `blocked`、`partial` 或 `input_missing`，不能伪造成功结果。

每个实际可见或可操作字段记录：

- `element_id`、`kind`、`tag`、`role` 和 `label`；
- 可见、启用、必填、只读、选中和值状态；
- 稳定定位器候选及可信度；
- 所属表单的 `field_element_ids`。

新增、编辑和新增子对象等相似弹窗应分别核对，不能直接假设字段、默认值或只读状态相同。

## 5. 操作边界

### 5.1 无副作用探索

可直接进行展开/收起、切换 Tab、打开下拉或日期面板、查看详情、翻页、横向滚动、打开确认弹窗以及输入后清除。每个会改变界面的操作仍需记录变化状态或明确记录无变化结论。

### 5.2 有副作用业务操作

新增、编辑、删除、启停、批量提交和启动采集等操作必须明确记录：

- 是否实际提交；
- 提交前后的页面状态；
- 测试数据责任边界；
- 清理方式和清理结果。

未获授权或无法清理时，不得继续假设业务结果，应记录相应阻塞状态。

## 6. 证据和脱敏

重要页面状态应保存原始比例截图和脱敏 DOM 快照，并在 `page.json` 的 `evidence` 中引用。截图前读取实际内容尺寸，不使用 CSS `zoom`、页面压缩或裁切来隐藏内容；页面存在横向溢出时，应覆盖实际内容宽度。

浮层应逐一打开、截图、关闭，避免上一个浮层遮挡后续状态。证据目录中未被 `page.json` 引用的截图和 DOM 快照应在人工复核后清理。

DOM、截图、日志和报告不得包含账号、密码、Token、Cookie、认证状态、内部地址或未经授权的业务隐私数据。脱敏后应同步更新 DOM 哈希和清单引用信息（如项目格式要求）。

## 7. 完成前人工复核

探索结束前人工核对：

1. 页面级、组件级、弹窗级和反馈状态范围是否已检查；
2. 每个会改变界面的控件是否有前后状态记录或无变化结论；
3. 展开字段是否进入 `elements` 和 `forms.field_element_ids`；
4. `interactions` 是否反映关键操作链路；
5. 重要状态是否有截图、DOM 和日志引用；
6. 有副作用操作是否记录提交和清理边界；
7. 未引用证据是否已清理，敏感信息是否已脱敏；
8. `page.json` 是否通过项目要求的 Schema 格式校验。

上述复核仅作为人工参考，不作为自动化页面探索门禁。
