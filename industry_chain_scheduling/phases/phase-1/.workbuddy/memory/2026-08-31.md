## 08_ui_automation 重构为统一 playwright + pytest 工程

**背景**：原先存在两条割裂流水线 —— 自研 runner `tests/run_case.py`/`run_module.py`
能产出 selection/results/bugs_review/xlsx，而 pytest 路径只产出 testcase.csv，
且 pytest 因自定义 `--headed` 与 pytest-playwright 0.9.0 同名选项冲突**根本启动不了**。

**交付**（用户确认的四项决策：统一 pytest / 保留 return-dict / 每 RUN 一个缺陷报告.md / 只交付框架不实跑）：

- 新增 `framework/` 内核包 3900 行（13 模块 + 9 个 reporter）+ 根 `conftest.py` + 3 个自检脚本。
- 删除 `tests/conftest.py`、`tests/run_case.py`、`tests/run_module.py`、`utils/`（含 Node 脚本）。
- **89 个用例（`tests/modules/**`）与 5 个 POM 零改动**；历史 31 个 RUN 目录与 656 张截图全部保留。

**关键技术点（踩过的坑）**：

1. `-p no:playwright` 是 P0 的正解（插件注册名是 `playwright` 不是 `pytest-playwright`）。
   禁用理由除 `--headed` 冲突外，更危险的是插件的 autouse session fixture
   `delete_output_dir` 会对 `--output` 目录执行 `shutil.rmtree`。
2. `pytest_runtest_makereport` 里把结果映射回 pytest 报告时，**skipped 的
   `rep.longrepr` 必须是 `(path, lineno, reason)` 三元组**（pytest 有 `assert isinstance(tuple)`），
   用字符串会 INTERNALERROR；failed 用字符串没问题。
3. 完整性校验必须拆两阶段：执行维度在写产物**之前**判，产物存在性必须在写**之后**判，
   否则每次真实运行都会因"产物缺失"被误判不完整（曾漏此点导致退出码恒为 7）。
4. `--allow-empty` 时 pytest 自身会因"未收集到测试"返回 5，需在 `finalize` 中
   对 exitstatus ∈ (0,5) 归一化覆盖。
5. `pythonpath = .`（pytest.ini，7.0+）一次性替代 3 处 `sys.path.insert` hack。
6. 数据登记 `data/REQ-*.yaml` 用**文本行级改写**而非整体 `yaml.safe_dump`，
   以保留原文件注释与键顺序（07_zentao_sync 的 `writeback_case_ids` 也是这个思路）。
7. 状态载体用 `config.stash[StashKey]` 挂 `RunOrchestrator`，替代 6 个模块级全局变量。
8. 产物写出三层保障：`pytest_sessionfinish`（主）+ `pytest_unconfigure`（无条件兜底）
   + `atexit`（最后网），并用 `results.jsonl` 增量落盘抗硬崩溃。
